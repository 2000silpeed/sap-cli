Overview

AI가 SAP 업무 경로를 기억하고, 실행 전에 설명합니다

sap_cli는 SAP GUI 화면의 구조와 확인된 경로를 UI 지도로 저장합니다. AI는 자연어 요청을 받으면 지도에서 목표까지의 전체 단계를 먼저 만들어 보여주고, 확인된 계획만 실행합니다.

1. 화면을 다시 찾느라 느려집니다

화면을 매번 전체 스캔하고 AI가 다음 동작을 즉석에서 추측하면 속도와 재현성이 떨어집니다. 지도는 이미 확인한 화면 구조와 이동 경로를 보존합니다.

2. AI와 사용자가 함께 지도를 완성합니다

안전하게 자동 이동할 수 없는 탭, 팝업, 조회 분기는 AI가 멈춰서 사용자에게 묻습니다. 사용자가 화면으로 이동하면 새 상태와 안전한 경로만 기존 지도에 추가합니다.

3. 실행은 미리 본 불변 계획만 허용합니다

계획에는 지도 버전과 fingerprint, 입력값, 성공 조건, 위험 단계가 고정됩니다. 실행 중 화면이 다르면 억지로 진행하지 않고 재계획 또는 지도 보강을 요청합니다.

UI Map Planning

지도 제작부터 실행까지

명령어를 모르는 사용자는 AI에게 업무 목적을 말하고, 필요한 화면 선택과 실행 승인만 합니다.

1. 지도 수집

map-traverse-start가 TCode의 현재 화면을 값 없이 기록합니다. 테스트 client에서는 되돌릴 수 있는 탭·트리 이동과 정확히 허용한 조회성 분기만 확장합니다.

2. 사용자 보강

AI가 경로를 확신하지 못하면 job을 멈추고 화면 이동을 요청합니다. 사용자가 도착한 화면은 map-augment-start와 재개 작업으로 지도에 덧붙입니다.

3. 계획 미리보기

plan-preview는 저장된 지도와 레시피만 읽어 전체 명령, 입력값, 성공 조건, 위험·승인 요건을 확정합니다. 이 단계에서는 SAP를 조작하거나 화면을 스캔하지 않습니다.

4. 한 번에 실행

plan-execute는 daemon 메모리의 계획을 단일 IPC로 실행합니다. 기본 cheap 검증은 scope·상태·모달·대상 요소만 확인하며 전체 화면 재스캔을 하지 않습니다.

나는 SAP 업무 담당자이며 스크립팅 경험이 없다. 테스트 client에서 MM03의 자재 기본 데이터 조회 화면 지도를 만들어줘. 저장·변경·전표 생성·승인·발송은 하지 말고, 안전하게 자동 이동할 수 없는 화면은 내게 물어봐. 지도가 준비되면 자연어 요청의 실행 계획을 먼저 보여주고, 내가 확인하기 전에는 실행하지 마.

지도·계획·실행의 세 겹 안전망

              

                
지도 scope
시스템, client, 언어, TCode가 다른 지도는 재사용하지 않습니다.

                
불변 계획
계획 ID, hash, 지도 버전과 fingerprint가 달라지면 실행을 중단합니다.

                
승인 토큰
저장·변경·전송 단계는 계획과 실행 agent에 묶인 일회용 승인 없이는 진행하지 않습니다.

                
cheap 검증
기본 실행은 전체 화면 스캔 대신 TCode, 상태바, 모달, 대상 요소만 확인합니다.

                
실행 이력
중복 실행은 막고, 결과와 오류는 값 노출 없이 작업 이력에 남깁니다.

              FAQ
              
자주 묻는 질문

            

          

          

            화면 지도와 온톨로지는 뭐가 다른가요?
            
화면 지도는 특정 시스템, client, 언어, TCode에서 실제로 수집한 화면과 경로입니다. 온톨로지는 트랜잭션과 업무 용어를 폭넓게 설명하는 지식 레이어입니다. 계획 실행은 버전과 scope가 고정된 화면 지도를 기준으로 합니다.

          

          

            AI가 모르는 화면을 만나면 어떻게 되나요?
            
AI는 임의로 버튼을 누르지 않고 needs_user_input으로 멈춥니다. 사용자가 화면으로 이동한 뒤 알려주면, 그 상태와 확인된 경로만 기존 지도에 추가합니다.

          

          

            계획 미리보기는 SAP를 조작하나요?
            
아닙니다. plan-preview는 저장된 지도와 레시피만 읽어 전체 step, 변수, 성공 조건, 위험과 승인 요건을 만듭니다. 실행할 수 있는 유효한 계획일 때만 daemon 메모리에 plan reference가 등록됩니다.

          

          

            왜 실행 때마다 전체 화면을 다시 읽지 않나요?
            
지도와 실행 계획을 이미 확정했기 때문입니다. 기본 cheap 검증은 현재 TCode, 상태바, 모달, 대상 요소의 가시성만 확인합니다. locator나 지도 scope가 달라지면 실패하고 새 계획 또는 지도 보강을 요구합니다.

          

          

            처음에 무엇부터 해보면 되나요?
            
테스트 client의 조회성 TCode 하나를 정합니다. AI에게 지도 제작을 요청하고, 누락 화면을 보강한 뒤, 같은 지도에서 조회 계획 미리보기와 실행을 순서대로 확인합니다.

          

          

            변경 업무도 같은 방식으로 실행할 수 있나요?
            
가능하지만 조회 업무와 달리 위험 단계를 미리보기에서 분리해야 합니다. 관리자가 계획 hash와 실행 agent에 묶인 일회용 승인 토큰을 발급한 뒤에만 저장·변경·전송 단계를 실행합니다.
